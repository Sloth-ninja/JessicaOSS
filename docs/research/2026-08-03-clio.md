# Clio integration research — 3 August 2026

> Owner decision 03/08/2026: the Quill/Unity integration is CANCELLED ("too
> clunky"); Clio is the first practice-management connector. The firm uses
> **Clio Manage** (day-to-day practice management, time recording, billing,
> matter permissions) and **Clio Grow** (client intake: conflict checks, KYC
> — see the firm's "Client Intake in Clio Grow Process" guide). Region: EU.
> Condensed from two research agents; endpoint evidence verified against the
> official OpenAPI specs (Manage v4, 166 paths; Grow "Clio Platform" v2, 19
> operations).

## Clio Manage (docs.developers.clio.com/clio-manage/api-reference/)

Wishlist verdicts: **supported** — time recording (`POST /activities`,
`quantity` is SECONDS in current API versions: pin `X-API-VERSION` or
misrecord by 3,600×), matter create/open, contact create, WIP & balances
(`billable_matters` unbilled WIP; `outstanding_client_balances` billed-unpaid),
contact/matter search-by-name, **documents** (three-step presigned upload —
POST metadata → PUT parts to signed URLs (10-min expiry) → PATCH
fully_uploaded; list/download/versions — the capability Unity lacked).
**Not in API** — bill creation (read/preview/state-PATCH only; humans
generate bills in Clio) and AML/ID verification (KYC data *fields* only,
UK-eligible).

**Permissions: explicitly documented** — "Even with the correct OAuth scope, a
user can only access data their Clio role permits"; 403 on violations,
redaction of invisible nested records. Satisfies the per-lawyer
confidentiality requirement by design (spike still verifies two-user). Note
the firm's intake guide REQUIRES matter permissions to be set in Manage —
so redaction is live at AGL, not theoretical.

Build facts: EU base `eu.app.clio.com/api/v4` (UK firms are EU-region; tokens
region-bound); OAuth auth-code, access tokens 30 days, refresh tokens
non-expiring; **scopes fixed at app registration** (changes force user
re-auth) — register final set up front: Matters/Contacts/Activities/Documents
RW, Billing R; 50 req/min per user token (peak 07:00–22:00 GMT); `fields=`
param mandatory discipline (default response is id+etag only); cursor
pagination; webhooks exist (HMAC-signed, expire ≤31 days — renewal cron
needed); no sandbox (7-day trial → developer account conversion).

## Clio Grow (docs.developers.clio.com/clio-grow/api-reference/)

**Separate developer stack** ("Clio Platform"): separate portal
(EU: `eu.developers.api.clio.com`), separate app, separate per-user OAuth.
EU hosts: authorise/token/revoke at `eu.auth.api.clio.com/oauth/*`, API base
`eu.api.clio.com/grow`. PKCE S256 supported. Access tokens 24 h; **refresh
tokens rotate on every use** (persist replacement atomically). Register as a
**private app with the Firm identifier** — skips Clio's app-approval process.

**The API is small — 19 operations, read-heavy.** Actual scopes:
lead_inbox R/W, custom_action R/W, matter R (READ-ONLY — no write endpoints
exist despite portal R/W checkboxes), matter_note R/W, contact R (read-only),
contact_note R/W, user R. **No forms, no documents/attachments, no webhooks,
no status writes, no PATCH/PUT anywhere.**

Capability vs the firm's intake pipeline: Jessica can **watch** (matter
`status` carries the firm's custom pipeline strings — "KYC Check", "Client
Approval" etc., `status_category` intake/hired/declined; polling via
`updated_since`, no webhooks), **feed** (POST /inbox_leads — person-shaped
only), **annotate** (POST matter/contact notes — the durable machine-readable
artefact; Jessica's Companies House conflict/KYB research lands here), and
**embed** (custom action button on the Grow matter page → deep link to
JessicaOS; single-use 60-s `custom_action_nonce` validates the clicking
user). Conflict-check forms, KYC uploads, status moves, and Convert-to-Manage
are API-invisible/human-driven. Converted records expose `clio_id` (the
Manage ID) — the cross-system join key.

Rate limit: **3 req/s per app shared across ALL users** (tight — frugal
polling only). Cursor pagination (`page_token`). Date-based `X-API-Version`.
No sandbox; Grow test account by emailing api.partnerships@clio.com.

## Registration + env contract

Two apps, two callbacks, two token sets (per-user each, AES-256-GCM path):

| | Manage | Grow (Platform) |
|---|---|---|
| Portal | developers.clio.com (EU account) | eu.developers.api.clio.com |
| Redirect URI | `https://api.jessicaoss.com/clio/oauth/callback` (+ `http://127.0.0.1:3001/...` — localhost literal banned) | `https://api.jessicaoss.com/clio-grow/oauth/callback` (+ 127.0.0.1 variant) |
| Scopes | Matters/Contacts/Activities/Documents RW, Billing R (+ webhooks if offered) | lead_inbox RW, custom_action RW, matter R, matter_note RW, contact R, contact_note RW, user R |
| Env | `CLIO_CLIENT_ID/SECRET`, `CLIO_REGION=eu` | `CLIO_GROW_CLIENT_ID/SECRET` (region shared) |

## Spike plan (go/no-go before any build)

Manage: token flow on EU hosts; `who am I`; list matters; **two-user
permissions test** (restricted matter invisible/redacted for the second
user — AGL uses matter permissions, so this is testable for real); one time
entry on a test matter (verify seconds semantics + attribution defaults);
document upload round-trip. Grow: token flow (verify EU portal registration);
read matters + verify the firm's custom status strings come through verbatim;
`updated_at` bumps on status change (the polling strategy rests on this);
custom-action parameter set; lead create/triage round-trip.
